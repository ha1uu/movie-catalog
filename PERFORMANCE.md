# Производительность после подключения TMDB

Предыдущие замеры относились к удалённой статической подборке. Они не подтверждают скорость приложения с внешним API, поэтому прежние цифры не используются как результат текущей версии.

Реальные FCP, LCP и CLS необходимо измерить после задания `NUXT_TMDB_READ_TOKEN` и разрешения доступа к `api.themoviedb.org` и `image.tmdb.org`. До этого live-проверка заблокирована отсутствующей конфигурацией.

Проверки текущей интеграции: production-сборка и проверка TypeScript проходят; 14 интеграционных тестов с отдельным тестовым HTTP-поставщиком успешны. Они проверяют запросы и интерфейс, но не заменяют live-запросы TMDB.

Сохранены SSR, локальные шрифты с `font-display: optional`, размеры и соотношения сторон изображений, lazy loading, skeleton-разметка и место под следующую порцию каталога. Ответы TMDB кешируются сервером на 5 минут.

Воспроизведение после настройки:

```bash
npm run build
# Запустите production с NUXT_TMDB_READ_TOKEN, затем:
npm run test:live
npm run test:perf
```

Скрипт сначала проверяет доступность API и определяет существующие ID фильма и персоны. Измерения выполняются в Chromium, с новым контекстом и отключённым HTTP-кешем: 1,6 Мбит/с, 150 мс, CPU ×4, viewport 1365 × 900. Предварительные API-запросы прогревают серверный кеш; время первичного SSR с холодным серверным кешем зависит от задержки TMDB и измеряется отдельно на хостинге. Нельзя выдавать скорость тестового поставщика или страницы ошибки за измерение реального каталога.
