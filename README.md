# Кадр — каталог фильмов на TMDB

Nuxt 3, Vue 3 и TypeScript. Фильмы, поиск, жанры, персоналии, актёрский состав, фильмографии и постеры загружаются из **TMDB API v3**. `server/data/catalog.ts` и локальная подборка удалены. Данные рендерятся на сервере через `useFetch`, затем следующие страницы загружаются через серверные маршруты Nuxt.

## Настройка и запуск

Нужен Node.js 22/24, npm и **API Read Access Token** TMDB. Получите его в [настройках TMDB API](https://www.themoviedb.org/settings/api). Приложение использует Bearer-аутентификацию; нужен Read Access Token, а не числовой Account ID.

```bash
npm ci
cp .env.example .env
```

Локально заполните `NUXT_TMDB_READ_TOKEN` в `.env`, который исключён из Git. В облаке или на хостинге задайте значение через защищённые runtime-настройки. Токен остаётся в private `runtimeConfig`, не включается в публичный payload и не передаётся браузеру. Разрешите исходящий HTTPS к `api.themoviedb.org` (сервер) и `image.tmdb.org` (изображения в браузере).

```bash
npm run dev
```

Production:

```bash
npm run typecheck
npm run build
# Передайте NUXT_TMDB_READ_TOKEN через окружение процесса:
NITRO_HOST=0.0.0.0 NITRO_PORT=3000 npm start
```

Production-сервер Node не читает `.env` автоматически. Передавайте переменную в runtime через хостинг или менеджер процессов; для локальной проверки можно запустить `node --env-file=.env .output/server/index.mjs`. Остановите dev-сервер перед сборкой.

Без токена API приложения возвращает **503**, а интерфейс показывает недоступность каталога. Статического fallback нет. Недоступный ресурс TMDB возвращает 404; ошибки авторизации и недоступность поставщика не превращаются в «фильм не найден».

## Работа API

- `GET /api/movies` — популярные фильмы. `genre`, `year`, `sort=popular|rating|newest`, `page`.
- `GET /api/movies?q=...&year=...` — поиск по названию. TMDB Search не поддерживает жанры и произвольную сортировку: при поиске эти элементы интерфейса отключены, прямой запрос с несовместимыми параметрами возвращает 400. Сброс поиска возвращает полный набор фильтров.
- `GET /api/movies/:id` — описание, рейтинг **TMDB**, длительность, российский возрастной рейтинг при наличии, режиссёр, актёры и рекомендации.
- `GET /api/people?page=...` — популярные персоны, с подгрузкой следующих страниц.
- `GET /api/people/:id?page=...` — биография, фото и фильмография без дублей, порции по 24 фильма.
- `GET /api/featured` — популярный фильм для главной, полученный из того же API.
- `GET /api/saved?ids=...` — актуальные данные сохранённых фильмов по TMDB ID. Избранное хранится в браузере; ID из старой демоверсии мигрируют.

Сервер кеширует успешные ответы TMDB на 5 минут и объединяет одинаковые запросы. Ошибки не подменяются данными. Сервис использует `ru-RU`; если перевод отсутствует, TMDB может вернуть оригинальное название или пустое описание. Для отсутствующих постеров и фото предусмотрены нейтральные placeholders.

Порции интерфейса содержат 12 фильмов. Адаптер объединяет/разрезает страницы TMDB по 20 результатов, сохраняя порядок и пагинацию. Лимит доступа TMDB — первые 500 страниц: интерфейс учитывает его при расчёте конца выдачи. Сортировка по рейтингу исключает фильмы с менее чем 300 голосами. Новинки ограничены уже вышедшими фильмами с 50 голосами.

## Проверки

```bash
npm run typecheck
npm test
```

`npm test` собирает production и автоматически поднимает **отдельный тестовый TMDB-подобный HTTP-сервер** на 4010 и два приложения на 3100/3101. Фикстуры находятся только в `tests/fixtures/`, не импортируются приложением и не включаются в production output. Эти тесты не требуют настоящего токена и **не доказывают доступ к реальному TMDB**.

Проверяются SSR без JavaScript, передача фильтров поставщику, склейка страниц по 20/12, поиск, фильмографии, infinite scroll, ошибки API/429/401, отсутствие токена в HTML, отсутствие статической подмены, избранное и мобильная навигация. Для браузерных тестов нужен Chromium (`CHROMIUM_PATH`, по умолчанию `/usr/bin/chromium`).

На отдельно запущенном приложении с настоящим токеном:

```bash
npm run test:live
npm run test:perf
```

`TEST_BASE_URL` выбирает адрес этого приложения (по умолчанию порт 3000). Live smoke запрашивает реальный каталог, фильм, персону и фильмографию. Performance-скрипт сначала требует рабочий API: замер страницы ошибки не считается успешной проверкой. Он измеряет FCP/CLS на главной, реальном фильме и персоне при холодном browser-кеше, 1,6 Мбит/с, 150 мс и CPU ×4. Серверный кеш при этом прогрет предварительными запросами; скорость с холодным кешем дополнительно зависит от TMDB. Цель FCP < 1500 мс необходимо подтвердить после настройки ключа и на выбранном хостинге.

## Структура

- `server/utils/tmdb.ts` — аутентификация, HTTPS proxy, таймаут, кеш и перевод ошибок TMDB.
- `server/utils/catalog.ts` — адаптер данных TMDB, фильтры и пагинация.
- `server/api/` — серверные маршруты приложения.
- `components/CatalogFeed.vue` — `useFetch`, skeleton и infinite scroll.
- `pages/` — SSR-страницы; `composables/useSaved.ts` — избранное.
- `tests/fixtures/` — изолированная тестовая имитация поставщика.

Атрибуция и ресурсы: [ASSETS.md](ASSETS.md). Состояние проверки производительности: [PERFORMANCE.md](PERFORMANCE.md).
